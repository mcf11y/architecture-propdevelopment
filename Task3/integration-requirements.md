# Задание 3, пункт 3. Требования к внешним интеграциям «Умный дом»

**Контекст:** новый сервис `smart-home-app` обращается к партнёрской платформе только через **Шлюз партнёрских API**. Обрабатываются биометрические ПДн (лицо, госномер) — особая категория по 152-ФЗ.

## 1. Требования к безопасности

- **Канал:** только TLS 1.2+; «Шлюз ↔ партнёр» — **mTLS** (обе стороны по сертификатам). Чувствительные данные не передаются в URL.
- **Изоляция по тенанту:** каждый запрос привязан к УК/ЖК, Шлюз проверяет права на объект. Закрывает дефект «одна УК видит данные другой».
- **Минимальные привилегии:** scope токена партнёра — только объекты его тенанта; прямой доступ партнёра в приватный контур запрещён, только через Шлюз.
- **Биометрия (152-ФЗ):** отдельное согласие; **минимизация** — хранить идентификатор привязки, а не шаблон (шаблон у партнёра); шифрование at-rest; удаление при отзыве.
- **Секреты:** ключи и сертификаты — в хранилище секретов с ротацией
- **Аудит и устойчивость:** журналирование всех обращений (для ИБ), rate limiting, валидация входящих событий, **fail-closed** — при сбое/ошибке auth авто-открытие не срабатывает (ручное открытие и звонок сохраняются).

## 2. Протоколы аутентификации и авторизации

| Канал | Аутентификация | Авторизация |
|---|---|---|
| Собственник → приложение | OIDC (`auth-service-1`), желательно MFA | проверка, что он собственник объекта |
| Приложение → `smart-home-app` | OAuth 2.0 / OIDC, **JWT** (короткоживущий) | scope/claims в токене |
| `smart-home-app` → Шлюз → партнёр (M2M) | **OAuth 2.0 Client Credentials + mTLS** | scope по тенанту (least privilege) |
| Партнёр → PropDevelopment (вебхуки) | **HMAC-подпись + mTLS**, защита от replay | события только по объектам тенанта |

Токены короткоживущие, JWT с проверкой `iss/aud/exp/scope`; секреты ротируются; компрометация одного тенанта не даёт доступа к другим.

## 3. Организация взаимодействия

```
Приложение ──(OIDC/JWT)──► smart-home-app ──► smart-home-db (права, привязки, журнал)
                                 ├─► auth-service-1 (аутентификация)
                                 ├─► tenant-core-app (права доступа к дому)
                                 └─► Шлюз API ──[firewall]──► партнёр ─► домофон / шлагбаум
```

- **Единая точка:** все вызовы партнёра — только через **Шлюз API** (централизованные политики ИБ, тенант-изоляция, журналирование).
- **Команды:** синхронно по **REST/HTTPS** (выдать доступ, открыть дверь); с ключом идемпотентности, retries/backoff и circuit breaker.
- **События:** асинхронно **вебхуками** (звонок домофона, проход, въезд) → push в приложение.
- **Контракт:** OpenAPI + версионирование; ревью ИБ на отсутствие лишних ПДн (дефект Task 2 — «контракты раскрывают ПДн»).
- **Сеть:** партнёр обращается только в DMZ к Шлюзу через firewall; внутренний контур недоступен напрямую.
- **Мониторинг/SLA:** аномалии интеграции — алерт ИБ; при недоступности партнёра — деградация в fail-closed.
